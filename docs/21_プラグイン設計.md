# FamilyRestaurant-Ultimate-LTS
# プラグイン設計書

---

# 1. 目的

本設計書では、FamilyRestaurant-Ultimate-LTSで利用する
プラグインシステムの仕様を定義する。

本体（Core）を書き換えることなく、新しい機能を追加・更新・削除できることを目的とする。

---

# 2. 基本方針

LTS本体は安定性を重視する。

追加機能はプラグインとして提供する。

例

Core

├── 注文

├── レジ

├── 厨房

├── 店長画面

└── API

　　　　↓

Plugins

├── Family Pay

├── AI店員

├── ガチャ追加パック

├── 季節イベント

├── 店舗テーマ

└── ミニゲーム

---

# 3. プラグイン構成

plugins/

├── familypay/

├── ai-staff/

├── minigame/

├── halloween/

└── sample-plugin/

各プラグインは独立したフォルダとして管理する。

---

# 4. プラグイン情報

各プラグインには

plugin.json

を配置する。

例

{
  "id": "familypay",
  "name": "Family Pay",
  "version": "1.0.0",
  "author": "Family Suite",
  "description": "Family Pay連携",
  "minCoreVersion": "1.0.0"
}

# 8. 権限

プラグインは必要な権限を宣言する。

例

・注文

・レジ

・API

・Socket.IO

・画像

・ログ

権限を持たない機能にはアクセスできない。

---

# 9. イベント

Coreはイベントを提供する。

例

OrderCreated

OrderUpdated

OrderCompleted

ReceiptPrinted

PaymentCompleted

StoreOpened

StoreClosed

プラグインは必要なイベントだけを受信する。

---

# 10. API

Core API

MenuAPI

OrderAPI

ReceiptAPI

KitchenAPI

StaffAPI

プラグインはCore APIを利用して動作する。

---

# 11. アップデート

プラグインごとに更新可能。

更新前にバックアップを作成する。

互換性がない場合は更新を中止する。

---

# 12. エラー

プラグインがクラッシュしても

Coreは停止しない。

問題のあるプラグインのみ無効化する。

# 15. Ultimate-LTS方針

Coreは「店舗運営に必要な最小機能」のみを持ち、
追加機能はすべてプラグインとして提供できる設計を採用する。

長期運用でもCoreを安定させながら、新しい機能を柔軟に追加できることを目標とする。
